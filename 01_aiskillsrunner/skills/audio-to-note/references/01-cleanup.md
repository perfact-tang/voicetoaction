# STT → 笔记：整理规则（逐语言）

这份规则只解决一件事：**把「说出来的话」变成「读得顺的文字」，但不改变说话人说了什么、按什么顺序说。**

它不是写作指南，不是文章改写指南。不要用博客、公文、论文的写法去「提升」一段口语；
笔记的价值在于忠实、清楚、保留说话人的判断和语气。

---

## 0. 一条总原则

> **能删的只有「怎么说」的噪声，不能删「说了什么」的内容。**

| 可以动 | 不能动 |
|---|---|
| 口头语、语气词、结巴、重复起头 | 观点、事实、例子、数字、专名、限定条件 |
| 明显的 ASR 错字、同音字、断句 | 说话人的叙事顺序、段落先后 |
| 标点、分段、数字/单位写法 | 语气、态度、确定性（「可能」不能改成「一定」） |
| 目标语言翻译（逐段对应） | 原文没有的理论、概念、建议、结论、背景 |

---

## 1. 通用步骤

1. **通读全文**，确认说话人从哪讲到哪、有几件事、顺序是什么。
2. **第一遍只删噪声**：语气词、结巴、重复起头、无意义的「然后/就是/那个」。
3. **第二遍补标点、断句**：按说话人的停顿和语义断句，不按字数硬切。
4. **第三遍分段**：只在话题自然转换处分段；话题顺序不变。
5. **第四遍回查**：数字、专名、否定、条件、因果是否都还在；有没有被自己「写顺」成原文没有的意思。
6. **最后才翻译**（如果目标语言与正文不同）：逐段翻译，保持段落数和顺序。

> 不要先翻译再整理，也不要把「整理」做成「重写」。

## 2. 中文（zh）

### 删什么

- 纯填充：嗯、啊、呃、额、那个、就是说、然后呢、这个、怎么说呢、对吧、你知道吗、我跟你讲（作为口头禅时）。
- 结巴/重复起头：「我我我觉得」→「我觉得」；「这个这个方案」→「这个方案」。
- 无意义重复：「就是说就是说」→「就是说」；「然后然后」→「然后」。
- ASR 常见的同音错字：按上下文改；不确定的专名不要猜。

### 保留什么

- 有语义的「但是」「所以」「不过」「其实」「说白了」——它们是说话人的转折和判断。
- 第一人称、口语感、情绪词；不要把「我觉得」改成「笔者认为」。
- 例子里的细节：人名、地名、时间、金额、数量、前后对比。
- 不确定表达：「可能」「大概」「我猜」「不一定」「要看情况」。

### 标点与分段

- 用全角标点：，。！？；：、「」。
- 一句话说完用「。」；疑问用「？」；不要每句都用感叹号。
- 一段只讲一个话题；话题变了才换段，通常 2–6 句一段。
- 不要加小标题、编号、项目符号（除非说话人自己就在说「第一…第二…」）。

### 示例

**STT 原文：**

> 嗯，那个，我今天想说的是，就是我们团队上周不是上线了一个新功能嘛，然后，然后其实效果没有想象中好，呃，我觉得主要原因是，怎么说呢，就是我们没有提前跟用户解释清楚，就是那个入口在哪里，然后用户就找不到，对，大概就是这样。

**整理后：**

> 我今天想说的是，我们团队上周上线了一个新功能，但效果没有想象中好。我觉得主要原因是，我们没有提前跟用户解释清楚入口在哪里，用户找不到。大概就是这样。

**注意：** 没有加「由此可见」「这说明了用户教育的重要性」；没有把「我觉得」改成「事实证明」；没有把「大概」删掉。

## 3. 日语（ja）

### 删什么

- 纯填充：えーと、あの、まあ、その、なんか、ちょっと（作为口头禅时）、ですね、そうですね（无实义时）。
- 结巴/重复：「ちょっとちょっと」→「ちょっと」；「あのあの」→ 删除。
- 无意义重复：「なんかこう」「まあまあ」按语境保留或删除。
- ASR 错字：汉字/假名转换错误按上下文修正；不确定的专名保留原样。

### 保留什么

- 说话人的断定/推测：「たぶん」「かもしれない」「と思う」「はず」。
- 敬体/常体的整体语体；不要为了「整齐」把です・ます全改成だ・である，或反过来。
- 语气终助词（よ、ね、かな、けど）中承载态度的部分；纯填充的「ね」可删。
- 具体数字、时间、地名、人名、产品名。

### 标点与分段

- 用「。」「、」；疑问用「？」也可以，但全文统一。
- 不要滥用「！」；不要用中文全角逗号「，」。
- 段落按话题转换分；不要加见出し（小标题）。
- 不要保留 ASR 产生的奇怪空格；日语正文通常不需要在汉字/假名之间加空格。

### 示例

**STT 原文：**

> えーと、今日はちょっと、あの、先週リリースした新機能について話します。まあ、結果としては、えーと、思ったより良くなくて、なんか、原因はたぶん、ユーザーに入口を説明していなかったことだと思います。あの、だから、みんながどこから使えばいいか分からなかった、という感じです。

**整理后：**

> 今日は、先週リリースした新機能について話します。結果としては、思ったより良くありませんでした。原因はたぶん、ユーザーに入口を説明していなかったことだと思います。だから、みんながどこから使えばいいか分からなかった、という感じです。

**注意：** 保留「たぶん」「と思います」「という感じです」；没有改成「〜に違いない」；没有加「したがって、UX の改善が急務です」。

## 4. 英语（en）

### 删什么

- 纯填充：um、uh、er、like（作为口头禅时）、you know、I mean、sort of、kind of、right?、okay so（无实义时）。
- 结巴/重复起头：「I I I think」→「I think」；「the the plan」→「the plan」。
- 无意义重复：「and and」→「and」。
- ASR 错词：按上下文修正；不确定的专名保留原样。

### 保留什么

- 说话人的判断和不确定性：「I think」「maybe」「probably」「I'm not sure」「kind of」中承载语义的部分。
- 第一人称、口语 contraction（don't / it's / we're）；不要改成正式书面语。
- 具体例子、数字、时间、对比、条件。
- 说话人的转折：「but」「though」「actually」「to be honest」。

### 标点与分段

- 标准英文标点；句首大写；句子之间一个空格。
- 不要每句都加感叹号；不要用中文全角标点。
- 按话题分段，通常 2–6 句一段；不要加 heading 或 bullet list。
- 数字、单位、货币按英文习惯写；原文明确说的数字必须保留。

### 示例

**STT 原文：**

> So, um, today I want to talk about, you know, the new feature we shipped last week. And, uh, honestly, it didn't do as well as we thought. I mean, I think the main reason is, like, we didn't explain to users where the entry point was. So, yeah, people just couldn't find it.

**整理后：**

> Today I want to talk about the new feature we shipped last week. Honestly, it didn't do as well as we thought. I think the main reason is that we didn't explain to users where the entry point was. So people just couldn't find it.

**注意：** 保留「I think」「Honestly」「just」；没有加「This highlights the importance of user education」；没有把「didn't do as well as we thought」改成「failed」。

## 5. 韩语（ko）

### 删什么

- 纯填充：음、어、그、저、뭐、약간（作为口头禅时）、그니까（无实义时）。
- 结巴/重复：「그 그」→「그」；「저는 저는」→「저는」。
- 无意义重复：「뭐뭐」→ 删除或按语境保留。
- ASR 错字：按上下文修正；不确定的专名保留原样。

### 保留什么

- 说话人的判断/推测：「아마」「것 같아요」「수도 있어요」「제 생각에는」。
- 敬语/半语的整体语体；不要为了「整齐」全部改成 합니다 或全部改成 해요。
- 具体数字、时间、地名、人名、产品名。
- 语气词中承载态度的部分；纯填充的「뭐」可删。

### 标点与分段

- 用「.」「,」「?」「!」；不要用中文全角标点。
- 段落按话题转换分；不要加小标题。
- 数字、单位按韩语习惯写；原文明确说的数字必须保留。

### 示例

**STT 原文：**

> 음, 오늘은 저희가 지난주에 출시한 새 기능에 대해 말씀드릴게요. 어, 그런데 결과는, 뭐, 생각보다 좋지 않았어요. 제 생각에는 아마 사용자들에게 진입점을 제대로 설명하지 않은 게 주요 원인인 것 같아요. 그래서 다들 어디서 써야 하는지 못 찾았던 것 같아요.

**整理后：**

> 오늘은 저희가 지난주에 출시한 새 기능에 대해 말씀드릴게요. 그런데 결과는 생각보다 좋지 않았어요. 제 생각에는 아마 사용자들에게 진입점을 제대로 설명하지 않은 것이 주요 원인인 것 같아요. 그래서 다들 어디서 써야 하는지 못 찾았던 것 같아요.

**注意：** 保留「아마」「것 같아요」；没有改成「반드시」「명백히」；没有加「따라서 UX 개선이 시급합니다」。

## 6. 跨语言翻译时的额外规则

当目标语言与 STT 正文语言不同时：

1. **逐段对应**：原文几段，译文几段；原文的顺序就是译文的顺序。
2. **不合并、不拆分**：不要把两段合成一段，也不要把一段拆成多段来「更好读」。
3. **保留不确定性**：maybe → たぶん / 可能 / 아마；不要升级成 definitely。
4. **保留第一人称和语气**：I think → 我觉得 / と思います / 제 생각에는。
5. **专名、产品名、代码、数字**：保留原样；不要音译到读者认不出来。
6. **不添加解释**：不要给外国读者补背景，也不要在括号里加原文没有的定义。
7. **不改变例子**：原文用 A 举例，译文仍然用 A，不要换成更「本地化」的例子。

## 7. 交付前自检（逐条打勾）

- [ ] 段落顺序与说话顺序一致，没有按逻辑重新编排。
- [ ] 没有新增小标题、编号、项目符号、总结段。
- [ ] 没有新增原文没有的概念、理论、建议、背景、数据、案例。
- [ ] 原文的数字、日期、金额、专名、否定、条件都还在。
- [ ] 「可能/大概/我觉得」等不确定性没有被写成确定结论。
- [ ] 删掉的只有口头语、结巴、重复、ASR 噪声。
- [ ] 目标语言正确；没有中英日韩混排（专名除外）。
- [ ] 标题来自原文内容，没有夸张或引入新概念。
- [ ] `笔记.json` 的 `body` 只有正文，没有标题、标签、URL、编辑说明。
- [ ] `hidden` 是 `false`，`docid` / `noteid` 与 `$DOCID` 一致。
