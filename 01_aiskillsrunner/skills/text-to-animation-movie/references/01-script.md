# 从文本到台词：论证链拆解与写法

## 1. 原文是素材，不是段落表

输入文本可能是文章、解说文案、会议记录、产品说明。**它的段落顺序不构成视频的结构。**

先做一遍审阅，写进 `分镜.md` 的前半：

- 这篇文章实际在回答**哪几个问题**？通常 3–5 个。
- 每个问题的答案是什么（作者的核心判断）？
- 哪些事实、案例、数字在支撑它？哪些只是铺垫、重复或岔题？
- 读者最容易卡在哪一步？那个地方要单独给一场。

### 举例：一篇讲星巴克与商业模式的文章

原文有 5 个中标题。拆成论证链后是 4 个问题：

| 问题 | 对应的原文内容 |
|---|---|
| 星巴克凭什么卖得更贵？ | 开篇的价格对比 |
| 它靠哪几个支点站住？ | 第三空间 / 店员 / 商品战略 / 门店运营 |
| 商业模式到底是什么？ | 狭义 vs 广义的定义 |
| 那它怎么搭起来？ | 三种路径 + 先简化再模式化 |

这个拆解让"三个支点""两种定义""三种路径"这些**并列结构**显出来 ——
它们才是分镜的形状来源，而不是原文的小标题。

## 2. 决定分镜数量

一条经验规则：

```
场景数 ≈ 目标时长(秒) / 7
```

一支 2 分 20 秒的片子约 18–20 场，平均每场 7 秒。太少会让画面长时间不动，
太多会让每场还没看清就切走。

每场承接 **1 行台词（24–34 字）**；需要展开时最多 2 行，合计不超过 55 字。
超过 2 行就考虑拆场。

## 3. 台词写法

### 长度

- **单行 24–34 字**。这是字幕两行能放下的长度，也是一口气能读完的长度。
- **一场 1 行**；最多 2 行，合计 ≤ 55 字。不要为了字幕短把一句话拆成 4、5 个 L 行。
- 全片总字数按 **4.2 汉字/秒** 反推（MeloTTS 实测，含停顿）：
  - 目标 2 分钟 → 约 480–530 汉字
  - 目标 2 分 30 秒 → 约 600–650 汉字
  - 目标 3 分钟 → 约 720–780 汉字

写完必须跑 `python3 scripts/build_audio.py --dry-run` 核对，不要靠估。

### 连贯性（比单行长度更重要）

配音是**按场景连读**的：同一场的 1–2 行会被拼成一段话送进 TTS。所以写的时候要把
它们当成一段话，而不是几句独立的句子。

- 行尾优先用 `，`，把话往下接；只有**一场的最后一行**用 `。` / `？`。
- **不要每行都收句号**。TTS 会在每个句号处重新起调，听起来就是「蹦字」。
- 换行是为了字幕不超宽，不是为了换气；两行之间要能一口气读下来。
- 场与场之间才留呼吸（画面切换处），场内不要靠句号硬断。

```jsonc
// 不好：每行都是独立句号，配音一顿一顿
["L01", "很多人以为 AI 只是回答问题。"],
["L02", "其实它还能记住上下文。"]

// 好：一句话说完，行尾用逗号接住
["L01", "很多人以为 AI 只是回答问题，"],
["L02", "其实它已经能记住你说过的每一句话。"]
```

### 语气

- 像**讲解**，不像朗读课文。可以用「那么」「其实」「也就是说」这类衔接词。
- 每场第一行尽量是个**完整的判断或问题**，不要以「接下来我们看」开头。
- 保留作者鲜明的判断和口吻；不要把所有话都改成中性陈述。
- 结尾不要写成"总之，以上就是……"的总结陈词。用一个判断、一个条件或一个悬念收尾。

### 与画面的分工

**台词说论点，画面给结构。** 不要把台词里已经说清楚的数字再画一遍长条
（除非对比本身就是重点），也不要在画面上堆台词的原句。

- 台词：「商业成功只看两件事：告知得多广，和多快获得信任。」
- 画面：两条进度条，一条 78% 一条 21%
- 而不是：把整句话原样印在画面上

### 术语与数字

- 专有名词（Product / Persona / Dashboard / SWOT / GA / 7-Eleven）保留原文，
  不要硬译；TTS 读英文会有点怪，可以接受。
- 数字用阿拉伯数字（「1991 家」而不是「一千九百九十一家」），TTS 和字幕都更清楚。
- 原文里无法确认的人名、公司名**不要点名**，用「某公司」「一位关键人物」这类表述。

## 4. 场景 ID 与视觉 ID

- 场景 ID：`S01`、`S02`…（两位，便于排序）
- 台词 ID：`L01`、`L02`…（全局唯一连续，LRC 与 timing 都按它索引）
- 视觉 ID：小写英文单词，描述这一场画什么，例如：

  | 视觉 ID | 画什么 |
  |---|---|
  | `hook` | 开场提问，一个物件对比 |
  | `pricedata` | 数据对比条 |
  | `thirdplace` | 同心圆/层级结构 |
  | `loop` | 循环示意图 |
  | `threepaths` | 三栏并列 |
  | `convert` | 漏斗/转化流程 |
  | `landing` | 收尾的结论图 |

命名原则：**一眼看出画的是什么**，不要用 `scene1`、`fig2` 这种无信息量的名字。

## 6. 写完之后的检查

```bash
cd "$DOC_DIR/engine"
python3 scripts/build_audio.py --dry-run
```

逐项确认：

- [ ] 没有 `!! over budget`（总时长超预算）
- [ ] 没有某场 `<- too long`（单场超过 18 秒）
- [ ] 场景数 ≈ 目标时长 / 7
- [ ] `script.json` 里每个 `visual` 都已在 `scenes.tsx` 的 `VISUALS` 里实现
- [ ] 台词 ID 连续且唯一
