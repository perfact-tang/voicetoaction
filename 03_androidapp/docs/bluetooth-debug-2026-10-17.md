**23:27–23:36 后续纯触控诊断补充：** 媒体模式下左双击、右前滑、右后滑两轮六次全部到达；Telecom 模式确认至少一次眼镜 HFP 挂断指令进入应用，共三次挂断回调，之后 SCO 断开。此前未捕获事件的结果仅适用于下面各自的早期测试，不能概括为“通话完全收不到操作”。完整证据及限制见 [眼镜触控诊断结果](huawei-touch-probe-results-2026-10-17.md)。

设备：Android 16 / 25080RABDR，HUAWEI Eyewear 2（经典 A2DP + HFP/SCO）。手机当前控制模式为 MEDIA，保留蓝牙麦克风。原设置为 AUTO，切换前已备份本地快照。

## 实测与证据

| 场景 | 结果 |
| --- | --- |
| 普通手机录音 | 正常启动、结束并保存 |
| AUTO / Telecom + 蓝牙麦克风 | AudioRecord 确认路由到眼镜输入；用户耳机操作未能结束录音 |
| MEDIA + 蓝牙麦克风，暂停保活 | 系统媒体按键可结束，眼镜实际双击/滑动仍无响应 |
| MEDIA + 蓝牙麦克风，持续同一条保活音轨 | 保活和 AudioRecord 都路由到眼镜；实际左双击、右前滑仍无响应 |
| 停止录音、释放 SCO 后左双击 | 成功收到 `KEYCODE_MEDIA_PAUSE`，触发“我在”和开始倒计时 |

早期测试使用左侧双击、右侧向前滑动、右侧向后滑动；当时右后滑尚未独立验证。后续纯诊断已覆盖三者在媒体模式下的两轮操作；通话模式的混合手势仍不能逐一归因。

## 厂商资料

[华为手势说明](https://consumer.huawei.com/cn/support/content/zh-cn15675559/)区分了播放/暂停、滑动音量以及可配置的切歌；并注明眼镜的接听/挂断控制不支持部分第三方网络通话。这是兼容性线索，不是本次 SCO 录音手势故障的最终根因证明。

[华为双击排查说明](https://consumer.huawei.com/cn/support/content/zh-cn15866150/)建议连续双击留出足够间隔。本次录音中的双击测试并非快速连续双击，停止录音后的对照则确实收到了事件。

## 已完成的代码修复

- 蓝牙路由协商、录音准备、PCM 收尾与 WAV 保存移出主线程，录音命令串行执行。
- 开始提示“我在”＋5 秒倒计时，结束提示“结束”＋10 秒确认；取消后立即停止倒计时和待播提示。
- 准备期间的结束/上传确认请求保留到实际准备或保存完成；不在文件尚未落盘时开始上传。
- 修复零时间戳 AVRCP 事件导致后续按键被永久判重的问题；普通音量、返回等按键不会被吞掉。
- MEDIA 录音保留同一条媒体保活；Telecom 接管时暂停媒体保活；不再为刷新状态重建音轨。
- 记录按键、实际 AudioRecord 路由、设备增减、HFP 状态、可用的系统音量变化及 TTS 播放回调。
- 保持蓝牙输入校验；录音期间观察到切回非蓝牙输入时停止并保存已录部分。

验证：67 个单元测试通过，`testDebugUnitTest assembleDebug lintDebug --no-configuration-cache` 通过。新增 instrumentation 测试已编译，实际执行被手机 USB 安装限制中断，不能标为实机测试通过。
